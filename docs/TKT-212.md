# TKT-212 — Transaction history endpoint

Advisors need to page through an account's transaction history in the portal.

## Endpoint

`GET /accounts/{account_id}/transactions`

| Query parameter | Type | Notes |
| --- | --- | --- |
| from | ISO date (YYYY-MM-DD) | Optional. Inclusive. Compared with the UTC date of `created_at`. |
| to | ISO date (YYYY-MM-DD) | Optional. Inclusive. Compared with the UTC date of `created_at`. |
| type | string | Optional. One of `deposit`, `withdrawal`, `transfer_in`, `transfer_out`. |
| limit | integer | Optional. Default 50, maximum 100. |
| cursor | string | Optional. Opaque value from a previous response's `next_cursor`. |

## Response

```json
{
  "items": [
    {"id": 812, "type": "deposit", "amount": "1500.00", "created_at": "2026-08-14T15:02:11+00:00"}
  ],
  "next_cursor": "opaque-string-or-null"
}
```

- Items are ordered newest first.
- `next_cursor` is `null` on the last page.
- Paging through the full result must never skip or repeat a transaction, even if new transactions arrive between page requests.

## Errors

- Unknown account: 404
- Invalid cursor: 400
- Invalid query parameters: 422
